# InkRAG 架构与发行验收

## 产品目标与当前实现

用户上传售后手册，核对解析结果，然后用一个查询获得足以回查的原文证据。开发者可以在进程内嵌入 SDK，企业团队可以用平台对候选试查、发布、撤销和回滚。工作台解决多人维护和授权问题，独立 SDK 解决本地接入和验证问题。

| 维度 | 当前判断 |
| --- | --- |
| 模块划分 | 解析、资产与检索分包合理，分别定义输出、事实与检索策略。SDK 与平台的存储生命周期不同，已发布 Python 和 HTTP 复用相同的平台查询规则。 |
| 底层结构 | 分词通过接口选择实现。词项、向量、节点来源的规则共享，SQLite 和 OpenSearch 各自消费。通过更换分词实现即可验证扩展边界。 |
| 平台结构 | PostgreSQL 存业务事实和发布指针。Rabbit 传递待执行信号。Worker 生成候选，OpenSearch 实际冻结后才能发布。已把正文限额与大文件背压从 API 装配拆出。主要技术债仍集中在 Repository、工作台和审校文件。后续应按资料、任务、发布、查询边界逐条迁移，并以行为测试保护事务和权限。 |
| 使用体验 | 「导入 → 预览 → 确认 → 等待 → 查询 → 回查原文」是主路径。术语和故障恢复在失败点提供解释。高级设置应保留清晰返回路径。教程以合成手册串联这些步骤。 |
| 实现进度 | 已有独立解析、SDK 入库和重开、真实队列、来源审校、两路检索、评测、版本发布和受限的引用回答。图检索、通用重排、超大清单属于另行验证的能力。 |

## 本轮发现和处理

| 问题 | 处理 |
| --- | --- |
| 重试消息已记录发送但没有 Worker 领取，任务可无限等待 | 超过交付宽限后按原状态重新投递，仍由数据库约束领取及提交。 |
| 构建预算允许生成消费者读不动的清单 | 统一写入和使用端安全上限，超限不能激活，原发布保持。 |
| 生产 OIDC 可能从发现文档接受明文 JWKS 端点 | 生产发现结果同样要求 HTTPS，并用可控密钥验证拒绝和成功路径。 |
| 两个相邻开发状态目录会共享 Compose 项目名，旧写入中断后状态可能缺失 | 新目录按自身路径产生独立作用域，恢复旧配置时保留旧命名和凭据。 |
| 开发停机只关闭依赖，留下 API、Worker 和模型 | 状态与停机都包含 Compose 应用配置，继续保留持久卷。 |
| 交换 JSON 经过原件上限，合规文件会在入库前被拒绝 | 使用交换格式的独立预算。 |
| Docling 从无扩展名展示名重新猜格式，富表格修订、排除标题或图片后可能继续导出旧内容 | 显式格式贯穿实际解析。导出和检索采用同一有效内容树，共享原文元素定位。 |
| 数据迁移进程加载了整套运行配置 | 迁移命令和 Compose 只向迁移入口提供运行档与迁移连接。 |
| 审校页面按浏览器补全后的 HTML 树猜原文位置 | 使用原件显式标签建立定位，保留安全净化。位置不明确时提示切换结构定位。 |
| 压测脚本发布了未选用资料的空候选 | 显式选用各解析版本并核对候选资料数，避免发布无资料的性能样本。 |
| 本地资产库缺表、格式标记损坏或持久记录无效 | 打开时核对格式和必需表，损坏记录返回稳定错误。 |

## 升级说明

节点处理版本升级为 3。已有平台发布仍可读，新候选按当前规则重建。SQLite 不会主动改写现有资料的片段，需要重新入库相应资料后才能更新旧富表格片段。新节点只有在解析器给出原文定位时才补该字段。

## 生产与公开发行边界

- 公开源码从已提交的白名单树导出。历史评测素材和原仓库历史留在工作区。项目代码与文档采用 Apache-2.0。私密漏洞报告入口及发行渠道仍须在实际公开仓库配置。
- 本轮目标是可运行、可复核的发行候选。部署方须完成目标环境的可用区故障转移、备份恢复、持续容量、企业 SSO 以及真实业务标注验收。生产拓扑及恢复流程见[部署方案](deployment.md)。
- 人工标注要覆盖关键型号、同义问法、近似编号、数据撤销及引用错误。当前中文关键词对照中 Jieba 前五完整证据覆盖 11/13，旧规则 12/13。编号用例分别 7/7 和 5/7，默认继续使用旧规则。[逐题结果](evidence/jieba-retrieval.json)


## 复验记录

| 入口 | 已观察结果 |
| --- | --- |
| Python SDK | 解析与检索分别在仓库外由 wheel 安装。禁用外网后，解析、资产重读、本地三路检索、精确编号和快照重开通过。测试向量用于验证链路。 |
| 真实依赖 | PostgreSQL 17、OpenSearch 3.3.2、RabbitMQ 4.4 和 MinIO 的定向回归通过。隔离工作台以 Keycloak、两个实际 TEI 模型进程及 Linux Worker 执行两条真实 HTTP 全链路。 |
| 数据库恢复 | 将合成栈的 PostgreSQL 18 逻辑备份恢复到新容器。受限运行角色可读取，知识库、资料、构建、发布、任务计数及迁移头一致。对象版本、搜索快照和跨机器切换待目标环境演练。 |
| 浏览器 | 七篇离线教程在 Chromium 的 1440、390、320 像素宽度上无横向溢出。四处交互、目录、键盘和课程代码示例已核对。工作台的上传四步走真实本地服务。 |
| 短测 | 修复前 36 次请求返回空候选。修复后 6 份合成资料进入候选，1/4/16 客户端并发共 36 次均返回命中。单机短测用于确认链路和统计工具。 |

还需单独验证目标机器架构、依赖/镜像供应链、真实企业身份、故障域、对象和搜索恢复，以及长期容量。当前未开展对外部署。
